# Privacy Auto-Anonymizer

**سامانه تعاملی پالایش خودکار داده‌های حساس در تصاویر و اسناد** — تشخیص چهره، پلاک خودرو و متون حاوی اطلاعات هویتی، با ماسک‌گذاری مقاوم در برابر حملات بازسازی و خروجی کاملاً سمت کلاینت.

پروژه پایانی کارشناسی مهندسی کامپیوتر — پشته فناوری: Python، Django، YOLOv8، EasyOCR/PaddleOCR/docTR، HTML5 Canvas، Tailwind CSS.

---

## ۱. معرفی کوتاه

کاربر یک تصویر (عکس صحنه، سند هویتی، نامه، فرم) را بارگذاری می‌کند. سرور با موتورهای تشخیص شیء و بازشناسی متن، نواحی حساس را استخراج کرده و فقط **مختصات** آن‌ها را به‌صورت JSON برمی‌گرداند. تمام رندر کادرها، تعامل کاربر و **ماسک‌گذاری نهایی روی Canvas مرورگر** انجام می‌شود؛ در نتیجه تصویر پالایش‌شده هرگز در سرور ساخته یا ذخیره نمی‌شود.

## ۲. قابلیت‌ها

**تشخیص چندلایه**
- چهره: YOLOv8-face با حاشیه امن (margin) برای پوشش کامل ناحیه صورت.
- پلاک خودرو: YOLOv8-plate؛ **هر** کاندید پلاک با بازشناسی متن داخل کادر اعتبارسنجی می‌شود — روی اسکن سند به‌صورت سخت‌گیرانه (متن کادر باید واقعاً شبیه پلاک باشد: کوتاه، با حداقل یک رقم و بدون حروف کوچک) و روی عکس به‌صورت منعطف (کادر ناخوانا نگه داشته می‌شود تا پلاک واقعی از دست نرود).
- متن: سه موتور قابل انتخاب — EasyOCR (پیش‌فرض)، PaddleOCR و docTR — با پیش‌پردازش اختصاصی (deskew مبتنی بر MRZ، blackhat morphology، CLAHE).
- تحلیل چیدمان سند (سه حالت): «Regex & Fuzzy» با بازسازی خطوط، «چیدمان هوشمند DocTR» با مدل LW-DETR (کلاس‌های DocLayNet؛ فقط نواحی متنی OCR می‌شوند و تصاویر/گرافیک‌ها نادیده می‌مانند) و «LayoutParser» با Detectron2.
  - نکته: `layoutparser` در ویندوز قابل نصب نیست (به `detectron2` نیاز دارد و Detectron2 روی PyPI منتشر نشده و wheel ویندوز ندارد)؛ به همین دلیل مسیر «چیدمان هوشمند DocTR» پیاده‌سازی شده که تنها به `python-doctr` (نصب‌شده) نیاز دارد و روی ویندوز هم کار می‌کند.

**بازشناسی اطلاعات هویتی (PII) روی متن OCR**
- اعتبارسنجی کوک‌سام: کارت اعتباری (Luhn / ISO 7812)، شبا (IBAN mod-97)، SSN (قواعد تخصیص SSA)، کد ملی ایران (چک‌سام ۱۱).
- MRZ پاسپورت/کارت شناسایی (ICAO Doc 9303) و انتساب نام استخراج‌شده به سایر بخش‌های صفحه.
- تلفن (Google libphonenumber + الگوهای NANP/ایران)، ایمیل، آدرس، کد پستی، IP، URL، تاریخ تولد، رمز/کلید API (با سنجش آنتروپی).
- نام اشخاص: قواعد زمینه‌ای (Dear/Mr./Name:/Sincerely) + مدل NER برت (dslim/bert-base-NER) به‌صورت اختیاری.
- نرمال‌سازی ارقام فارسی/عربی و اصلاح خطاهای رایج OCR درون رشته‌های عددی (`l→1`، `O→0`).

**استدلال‌گر Imajev (اختیاری)**
- مسیریابی صحنه: تفکیک سند/فرم از صحنه خیابانی برای صرف‌نظر کردن از OCR بی‌فایده.
- اعتبارسنجی کادرهای کم‌اطمینان با «تصمیم نوع‌دار» و احتمال عدم‌قطعیت (Unknown).
- سیاست **fail-open**: اگر اعتبارسنج از کار بیفتد، عنصر حذف نمی‌شود؛ چون حذف اشتباه یک چهره واقعی به معنای لو رفتن آن است.
- در صورت اجرای سرور محلی Imajev (`IMAJEV_ENDPOINT`)، استنتاج به آن منتقل می‌شود؛ در غیر این صورت موتور هیوریستیک داخلی پاسخ می‌دهد.

**رابط کاربری**
- ماسک‌گذاری تعاملی: کلیک روی کادر یا برچسب هر عنصر (هدفون انسانی ReGenHuman).
- **رسم دستی ناحیه:** کشیدن ماوس روی فضای خالی تصویر یک مستطیل انتخابی زنده (خط‌چین فیروزه‌ای/کهربایی) می‌سازد؛ نواحی سفارشی (مثل امضای دست‌نویس یا مُهر) به‌عنوان عنصر `CUSTOM` با ماسک فعال اضافه و با × روی برچسب حذف می‌شوند؛ این نواحی در تحلیل مجدد نیز حفظ می‌گردند.
- فیلتر چهره/پلاک: **DP-Pix** (میانگین بلوکی + نویز گاوسی سطح-شبکه پیش از وارون‌نگاری) و متن/ناحیه دستی: **بلوک سیاه صفر-آنتروپی**.
- برچسب‌ها و خطوط راهنمای HUD با `ResizeObserver` در طول انیمیشن‌های چیدمان (باز/بستن پنل ترمینال، تغییر اندازهٔ پنجره) دقیق بازمُحاسبه می‌شوند.
- مقایسه قبل/بعد با نگه‌داشتن دکمه یا کلید `Space`؛ سانسور خودکار همه؛ انتخاب/لغو گروهی.
- خروجی PNG در رزولوشن اصلی، بدون خط راهنما، کادر رنگی یا برچسب.
- RTL فارسی، Tailwind و فونت‌های Vazirmatn/Inter/JetBrains Mono به‌صورت **محلی** (بدون نیاز به اینترنت).

## ۳. معماری و جریان داده

```
┌──────────────┐   multipart    ┌──────────────────────────────────────┐
│   مرورگر     │ ─────────────▶ │  Django: /api/analyze/               │
│  (Canvas)    │                │  ┌────────────────────────────────┐  │
│              │                │  │ ml_pipeline.py                 │  │
│ ۱. آپلود     │                │  │  YOLO face ─┐                  │  │
│ ۵. رندر کادر │                │  │  YOLO plate ─┤ آبشار اعتبارسنجی │  │
│ ۶. ماسک      │                │  │  OCR text ───┘                 │  │
│ ۷. خروجی PNG │                │  │  pii.py  → PII spans           │  │
│              │ ◀───────────── │  │  Imajev  → تصمیم نوع‌دار        │  │
└──────────────┘  JSON مختصات   │  └────────────────────────────────┘  │
                                └──────────────────────────────────────┘
```

1. تصویر **فقط در حافظه** خوانده می‌شود (`FILE_UPLOAD_MAX_MEMORY_SIZE`) و هیچ فایلی روی دیسک نوشته نمی‌شود.
2. خط لوله تشخیص، کادرها و چندضلعی (polygon) هر عنصر را در مختصات اصلی تصویر برمی‌گرداند.
3. مرورگر کادرها را به‌صورت HUD تعاملی (خط راهنمای SVG + برچسب HTML) رسم می‌کند.
4. ماسک‌گذاری نهایی روی خود Canvas انجام می‌شود و خروجی مستقیماً دانلود می‌گردد.

```
anonymizer/
├── ml_pipeline.py   # خط لوله تشخیص (YOLO + OCR + Imajev + نقشه‌برداری span→polygon)
├── pii.py           # شناساگرهای PII با اعتبارسنجی کوک‌سام و زمینه‌ای
├── filters.py       # فیلترهای سمت سرور: DP-Pix، بلوک سیاه، بلور سنگین
├── views.py         # صفحه اصلی + API JSON
└── tests.py         # ۱۳۱ تست واحد/یکپارچه (بدون بارگذاری مدل)
config/              # تنظیمات Django (settings/urls/wsgi)
templates/anonymizer/index.html
static/{css,js,fonts,vendor}/
weights/             # وزن‌های مدل (در گیت نیست؛ در اولین اجرا دانلود می‌شود)
```

## ۴. نصب و راه‌اندازی

پیش‌نیاز: Python 3.10+ (توسعه با 3.12 انجام شده است).

```bash
python -m venv venv
# Windows
venv\Scripts\activate
# Linux/macOS
source venv/bin/activate

pip install -r requirements.txt
python manage.py migrate          # فقط برای دیتابیس پیش‌فرض Django
python manage.py runserver
```

سپس <http://127.0.0.1:8000/> را باز کنید.

**اولین اجرا:** وزن‌های مدل‌ها به‌طور خودکار دانلود می‌شوند (ناشناس‌سازی/پلاک: حدود ۶ مگابایت هرکدام، مدل‌های EasyOCR، و در صورت فعال بودن NER حدود ۴۰۰ مگابایت). برای شبیه‌سازی آفلاین، فایل‌ها را از قبل در `weights/` قرار دهید.

**موتورهای اختیاری:** اگر `paddleocr`/`docTR`/`LayoutParser` نصب نباشند، گزینه‌های متناظر در رابط کاربری به‌صورت غیرفعال («نصب نشده») نمایش داده می‌شوند و خط لوله به EasyOCR/Regex برمی‌گردد. مدل چیدمان DocTR در اولین استفاده حدود ۶۰ مگابایت دانلود می‌شود و در `~/.cache/doctr` (لینوکس/مک: مسیر مشابه) کش می‌شود. (تنظیم `layoutparser` به `detectron2` نیاز دارد که wheel ویندوز ندارد؛ برای ویندوز از «چیدمان هوشمند DocTR» استفاده کنید.)

## ۵. نحوه استفاده

1. تصویر را از دکمه «بارگذاری تصویر» یا با کشیدن و رها کردن در ناحیه کار بارگذاری کنید.
2. موتور OCR و روش تحلیل چیدمان را انتخاب کنید؛ تغییر هر انتخاب باعث **تحلیل مجدد خودکار** می‌شود.
3. در صورت نیاز «استدلال‌گر هوشمند Imajev» را روشن کنید تا پنل ترمینال تصمیم‌ها را زنده نمایش دهد.
4. کادرهای پیشنهادی روی تصویر ظاهر می‌شوند؛ با کلیک روی هر کادر یا برچسب آن، ماسک فعال/غیرفعال می‌شود.
5. با «سانسور خودکار همه» یا «انتخاب همه» می‌توانید همه عناصر را یکجا ماسک کنید.
6. برای بازبینی، دکمه «مقایسه قبل/بعد» را نگه دارید (یا کلید `Space`).
7. «استخراج تصویر نهایی» یک PNG با رزولوشن اصلی و فقط ماسک‌های فعال دانلود می‌کند.

## ۶. API

`POST /api/analyze/` — `multipart/form-data`

| فیلد | نوع | توضیح |
|---|---|---|
| `image` | file | تصویر ورودی (JPG/PNG/WEBP)؛ حداکثر ۳۰ مگابایت |
| `conf_threshold` | float | آستانه اطمینان آشکارساز (پیش‌فرض ۰٫۴۰، محدود به بازه ۰٫۰۵–۰٫۹۵) |
| `ocr_engine` | str | `easyocr` \| `paddleocr` \| `doctr` |
| `layout_engine` | str | `regex` \| `doctr_layout` \| `layoutparser` |
| `use_imajev` | bool | `true` \| `false` |

پاسخ (نمونه):

```json
{
  "status": "success",
  "image_dimensions": {"width": 1200, "height": 800},
  "detections": [
    {"id": 1, "type": "face",  "bbox": [120, 90, 240, 210], "polygon": [[120,90],[240,90],[240,210],[120,210]], "score": 0.91},
    {"id": 2, "type": "text",  "entity": "CREDIT_CARD", "label": "Credit card", "text": "4111 1111 1111 1111", "bbox": [...], "polygon": [...], "score": 0.94}
  ],
  "imajev_logs": []
}
```

نمونه فراخوانی با curl (توکن CSRF از کوکی خوانده می‌شود):

```bash
curl -c cookies.txt http://127.0.0.1:8000/ -o /dev/null
TOKEN=$(grep csrftoken cookies.txt | awk '{print $7}')
curl -b cookies.txt -H "X-CSRFToken: $TOKEN" -F "image=@doc.jpg" http://127.0.0.1:8000/api/analyze/
```

## ۷. حریم‌خصوصی و امنیت

- **پردازش در حافظه:** تصویر با `np.frombuffer`/`cv2.imdecode` رمزگشایی می‌شود و هیچ نسخه‌ای روی دیسک نوشته نمی‌شود؛ سقف `FILE_UPLOAD_MAX_MEMORY_SIZE` در تنظیمات برای همین منظور بالا برده شده است (پیش‌فرض جنگو ۲٫۵ مگابایت است و فایل‌های بزرگ‌تر را موقتاً روی دیسک می‌نویسد).
- **خروجی سمت کلاینت:** ماسک در مرورگر اعمال می‌شود؛ سرور حتی تصویر پالایش‌شده را هم تولید نمی‌کند.
- **محافظت CSRF** روی API، محدودیت حجم آپلود (HTTP 413)، محدودیت ابعاد تصویر (۶۰ مگاپیکسل) و اعتبارسنجی لیست سفید پارامترها.
- **بدون لاگ حاوی داده حساس:** پیام‌های خطا فقط نوع خطا را برمی‌گردانند و متن استخراج‌شده هرگز در کنسول سرور چاپ نمی‌شود.
- کلید `SECRET_KEY` و `DEBUG` و `ALLOWED_HOSTS` از متغیرهای محیطی خوانده می‌شوند (مقادیر پیش‌فرض فقط برای توسعه‌اند).

**چرا بلور ساده استفاده نمی‌شود؟** مقاله‌های Privacy Blur (arXiv:2512.16086) و Revelio (arXiv:2506.12344) نشان می‌دهند بلور گاوسی تا ۹۵٫۹٪ با مدل‌های دیفیوژن قابل معکوس‌سازی است؛ به همین دلیل پیش‌فرض چهره/پلاک **DP-Pix** و برای متن **بلوک سیاه صفر-آنتروپی** است.

## ۱۰. متغیرهای محیطی

| متغیر | پیش‌فرض | توضیح |
|---|---|---|
| `OCR_LANGS` | `en` | زبان‌های EasyOCR، مثال: `en,fa` |
| `ENABLE_NER` | `1` | فعال/غیرفعال کردن مدل NER نام اشخاص (`0` = خاموش) |
| `PRELOAD_MODELS` | `1` | پیش‌بارگذاری مدل‌ها هنگام `runserver` (`0` = خاموش) |
| `IMAJEV_ENDPOINT` | `http://127.0.0.1:8765/v1/systemone` | آدرس سرور اختیاری Imajev |
| `IMAJEV_TIMEOUT` | `2.0` | مهلت درخواست استنتاج از سرور Imajev (ثانیه) |
| `IMAJEV_REMOTE_COOLDOWN` | `120` | پس از یک خطای اتصال، این تعداد ثانیه از تماس مجدد با سرور Imajev صرف‌نظر می‌شود |
| `DOCTR_LAYOUT_ARCH` | `lw_detr_s` | معماری مدل چیدمان docTR (مثال: `lw_detr_m` برای دقت بالاتر و کندی بیشتر) |
| `DJANGO_SECRET_KEY` / `DJANGO_DEBUG` / `DJANGO_ALLOWED_HOSTS` | توسعه‌ای | تنظیمات استقرار |
| `ANONYMIZER_LOG_LEVEL` | `INFO` | سطح لاگ مؤلفه `anonymizer` |

## ۱۱. محدودیت‌ها و مسیر آینده

**مقایسه عملی موتورهای OCR (روی سند آزمایشی پروژه، ۸ خط متن انگلیسی/عددی):**

| موتور | خطوط خوانده‌شده | نکته اندازه‌گیری‌شده |
|---|---|---|
| EasyOCR (پیش‌فرض) | ۸ از ۸ | پارانتز تلفن، گروه‌های رقمی کارت و IP را درست می‌خواند |
| docTR (crnn_vgg16_bn) | ۸ از ۸ | اعداد قالب‌دار را به‌هم می‌ریزد: `(159) 357-8426` → `1 9) ( 357-8426` و `4111 1111 1111 1111` → `41 11 I - 11 11 1 1111`؛ برای متن سادهٔ انگلیسی (نام، ایمیل، آدرس) دقیق است |

نتیجه: برای سندهای دارای تلفن/کارت/IP، ترکیب **«چیدمان هوشمند DocTR» + موتور EasyOCR** بهترین حالت است (چیدمان را DocTR می‌دهد و متن را EasyOCR می‌خواند). در حالت ترکیبی، تشخیص‌های متنی روی هر بلوک جداگانه OCR می‌شوند و کیفیت (مثلاً کامل بودن ایمیل و امتیاز اطمینان) بهتر می‌شود.

- تشخیص متن فارسی در اسناد به موتورهای OCR وابسته است (EasyOCR با `OCR_LANGS=en,fa` یا PaddleOCR)؛ تشخیص‌گر پیش‌فرض docTR فقط لاتین است.
- الگوهای آدرس/تاریخ در درجه اول برای اسناد انگلیسی طراحی شده‌اند؛ افزودن الگوهای فارسی گام بعدی است.
- مدل‌های تشخیص چهره/پلاک عمومی‌اند؛ برای دقت بالاتر می‌توان آن‌ها را روی دامنه هدف fine-tune کرد. آشکارساز پلاک قبلاً روی متن معمول سند («Utility Bill»، «Ref: 88294»، «Billing Currency: USD ($)») با اطمینان ۰٫۶ تا ۰٫۸ فعال می‌شد؛ حالا هر کاندید پلاک با OCR داخل کادر اعتبارسنجی می‌شود و روی اسناد این کادرهای جعلی حذف می‌شوند (قاعده‌ی «فقط پلاک واقعی می‌تواند متن داخل خود را پوشش دهد» نیز حفظ شده است).
- اعداد مرجع سند (Ref / Invoice / Order / Tracking / Serial) دیگر به‌عنوان داده‌ی هویتی علامت نمی‌خورند؛ شناسه‌های وابسته به شخص (Account / Client / Patient / Passport / Policy و…) مثل قبل حساس هستند.
- برای استقرار واقعی: `DEBUG=0`، اجرای زیر WSGI، `collectstatic` و سرو کردن فایل‌های استاتیک.

## ۱۲. مجوز و قدردانی

کد این پروژه برای ارائه دانشگاهی نوشته شده است. کتابخانه‌های استفاده‌شده (Ultralytics YOLOv8، EasyOCR، PaddleOCR، docTR، transformers، phonenumbers) تابع مجوزهای خودشان هستند؛ وزن‌های مدل در مخزن قرار ندارند و در اولین اجرا دانلود می‌شوند.
